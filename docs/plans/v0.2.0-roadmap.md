### M1 — Canonical core (~2 weeks)

Goal: every artifact is content-addressed and hash-linked into an append-only DAG.

Tasks:
1. Implement dag-cbor canonical serialization (deterministic CBOR per IPLD spec, sha2-256 multihash, CIDv1). Ban floats; represent costs as integer micro-units. Emit JCS-JSON view alongside, labeled non-normative.
2. Artifact model: DeliberationManifest (root), Question, EvidenceLedger (entries link source bytes by CID), PanelManifest (PersonaManifest@version), ProtocolParams, Round chain (index, prev CID, turns[], distilledSummary CID, ML-DSA attestation), Turn (persona CID, inputContextHash CID, modelId, samplingParams, seed, output CID, citations[]), Verdict (round CID, decision, votes[], dissents[], signature).
3. Retry/supersede semantics: aborted rounds stay in DAG marked `status: aborted` with failure reason; `supersedes: CID → Round`. Struck turns stay marked with Marshall's objection linked. Nothing deleted.
4. `codecVersion` field frozen per artifact so future canonical-encoder fixes are a new codec version, never a silent change.
5. Cross-checked CID test vectors vs. reference IPLD implementations; property tests on canonical-form stability.
6. Python package layout: `conclave_core/` (pure Python, no Serverpod deps, reusable from the CC skill via CLI).

Exit criteria: independent property tests pass; a sample manifest round-trips through canonicalization with stable CIDs; codecVersion present on all artifact types.

### M2 — Signing & transparency log (~2 weeks)

Goal: verification requires no trust in the Conclave operator.

Tasks:
1. ML-DSA-65 (FIPS 204, category 3) via pqcrypto. Three key roles:
   - Conclave identity key: signs verdicts, appeal outcomes, transparency-log checkpoints. Long-lived, HSM/KMS-held in production, published fingerprint.
   - Session orchestrator key: signs per-round attestations + session manifest. Ephemeral per deliberation; cert chain: identity key signs (session pubkey + manifest CID).
   - Persona registry key: signs PersonaManifest versions. Long-lived; enables third-party persona authorship later.
2. Signature payloads are CIDs (hash-then-sign). ML-DSA-65 signatures ~3,309 bytes, constant regardless of artifact size.
3. RFC 6962 append-only Merkle transparency log over verdict CIDs; signed tree heads published periodically; inclusion proofs + consistency proofs.
4. Independent verifier CLI: validates a full synthetic case offline from artifacts + public keys alone (recompute every hash, check every signature).
5. Dogfood pqcrypto's ML-DSA path with real key lifecycle, cert-chain semantics, verification tooling.

Exit criteria: verifier CLI validates a synthetic case offline; inclusion + consistency proofs green; real key lifecycle exercised (not just KAT vectors).

### M4 — Token architecture (~3–4 weeks)

Goal: ~70–90% cost reduction vs the v0.1 baseline / ≤30% of cascaded baseline.

Tasks (five compounding axes):
1. Prompt caching: restructure every persona call as [shared static prefix: protocol rules + evidence ledger + panel roster] + [shared dynamic middle: distilled round summaries] + [persona-specific suffix]. Static prefix written to cache once per deliberation, hit at 0.1× input price.
2. Structured distillation: after each round, cheap-model pass emits a Summary artifact (positions, claims with citation CIDs, open disagreements, vote-relevant deltas), hard-capped ~1,200 tokens/round. Subsequent rounds carry only distilled summaries. Summary is content-addressed; inputContextHash proves which raw turns it distilled. Distiller prompt mandates preserving every seat's position incl. minority-of-one; dissenting personas may flag summary-fidelity objections forcing a one-shot re-distill with verbatim quote.
3. Model cascade:
   - Vote tallying, formatting, schema validation, summary distillation, consensus detection → Haiku-class (or local)
   - Standard persona turns, opening statements → Sonnet-class
   - Inner Sanctum synthesis, verdict drafting, tie-breaks, Tier-B appellate review → Opus-class
   - Rough split: ~70% Sonnet, ~25% Haiku/local, ~5% Opus. Dynamic escalation: contentious round → synthesis escalates one tier.
4. Sparse topology: rounds 1–2 run in committees (tier-aligned subsets of 5–7 seats in parallel); round 3 cross-committee challenge (each committee's distilled position attacked by one delegate from each other committee); round 4 full council on distilled outputs only. Turn count drops from 84 to ~45–55. Silent seats still vote reading distilled record.
5. Early exit, memoization, batching:
   - Consensus detection after each round (Haiku pass or embedding cosine over position statements); above threshold with no active dissent → skip remaining challenge rounds, go to verdict.
   - Deliberation memoization: content-hash (question + ledger + protocol params) triple; on collision offer replay-with-adaptation via single Opus pass reviewing prior verdict against context delta; new verdict links precedent CID (citable case-law graph).
   - Batch API: non-interactive rounds run through Batches for flat 50% discount; interactive/live-streamed civic sessions forgo it.
   - Multi-persona packing sparingly (same-committee turns only, to avoid v0.1 leakage).
6. Local models for mechanical tier: Ollama/llama.cpp 8–14B instruct for tallying, schema validation, canonicalization checks, first-pass distillation; cloud-Haiku fallback; promote local outputs only where deterministic validator checks them.
7. Per-turn telemetry artifact (tokens in/out, cache hit ratio, model, latency, cost in integer micro-USD), content-addressed.
8. Cost model lives in code: re-runnable estimator over telemetry schema.

Exit criteria: measured cost on 10 benchmark deliberations ≤30% of cascaded baseline; distillation-fidelity spot audits pass; per-turn telemetry artifacts content-addressed.

### M5 — Appeals (~3 weeks)

Goal: every verdict is final unless a valid appeal trigger fires within the finality window.

Tasks:
1. Dissent registration: every voting persona either joins majority or files a signed Dissent artifact (own CID, linked from Verdict), citing specific ledger evidence and prior turns (by CID) the majority allegedly misweighed. Dissents appear permanently in published verdict document.
2. Appeal triggers (grounds-based):
   - T1: New evidence — material evidence not in frozen ledger. Standing: any party. Window: configurable, default 30 days civic use. Gate: Marshall screens materiality (signed screening verdict).
   - T2: Procedural violation (uncited claim survived, quorum miscount, ledger tampering). Standing: anyone. No limit for integrity violations. Gate: mechanical verification against DAG; violations proven by hash/signature check auto-grant appeal.
   - T3: Dissent threshold ≥30% of voting weight dissented. Automatic. Immediate. No gate; auto-schedules one appellate review.
   - T4: Stakeholder petition (civic mode) — deferred to v0.3 (needs eSiasa-side identity work).
3. Escalation ladder:
   - Tier A: Re-deliberation with expanded context (same panel, fresh instances; original distilled record + appeal grounds + admitted new evidence as signed ledger supplement preserving original ledger CID). Handles T1.
   - Tier B: Adversarial appellate panel (disjoint seat draw, Kleros-style fresh jury + mandated advocatus diaboli steelmaning the dissent). Reviews hashed record, scope = appeal grounds only. Output: affirm / reverse / remand (order new Tier-A with corrected procedure).
   - Tier C: Human arbiter. Final and mandatory terminus. Named human or human panel (eSiasa: designated review board) receives full verifiable record and rules. Ruling signed and closes case. No fully-automated finality for civic decisions.
4. Every appeal artifact (petition, screening decision, appellate verdict, arbiter ruling) links original DeliberationManifest CID and enters transparency log.
5. Anti-abuse: appeals per case capped (default one per trigger class); Tier B convening requires granted T1/T2 or automatic T3; repeat frivolous T4 petitions burn petitioner class's threshold credit.
6. End-to-end appeal on a seeded procedural violation, caught by public verification, reversed on appeal.

Exit criteria: dissents register as first-class signed artifacts; T1–T3 triggers function; end-to-end appeal reverses a seeded procedural violation via public verification.

### M6 — conclave_server (~4 weeks)

Goal: live protocol host with persistence, streaming, budgets.

Tasks:
1. Postgres artifact store: `artifacts` table (cid PK, canonical bytes, type tag, created_at — never updated, never deleted) + relational projections (deliberations, rounds, turns, verdicts, appeals) as pure indexes over artifact CIDs; projections rebuildable.
2. Transparency log: `log_entries` table with tree-size-indexed Merkle nodes + `signed_tree_heads` table.
3. Redis (Memorystore): live session state — active deliberation FSM position, cache-warmth timers, per-session token budget counters, pub/sub fan-out for progress events.
4. Serverpod endpoints (session-authenticated; civic-public reads unauthenticated):
   - `convene(Question, EvidenceLedgerDraft, ProtocolParams) → CaseRef`
   - `watch(CaseRef) → Stream<DeliberationEvent>` (round started / turn committed / summary / consensus score / verdict)
   - `verdict(CaseRef) → VerdictBundle` (verdict + dissents + proofs)
   - `petition(CaseRef, AppealGrounds) → AppealRef`
   - `screening(AppealRef) → ScreeningResult`
   - `verify` (public): `artifact(Cid) → ArtifactBytes`, `prove(Cid verdictCid) → InclusionProof`, `latestSTH() → SignedTreeHead`
5. Budget enforcement in orchestrator: hard token budget per deliberation; graceful degradation order (drop to Batch → tighten sparse topology → early-verdict with reduced rounds flagged in manifest) — never silent quality reduction.
6. Kill/resume mid-round leaves a clean DAG.
7. Two concurrent live deliberations streamed to a test client.

Exit criteria: two concurrent live deliberations stream to a test client; kill/resume produces clean DAG; verify endpoint serves artifacts + proofs publicly.
